# FoodScope 事实型双栏简报设计

## 目标

将简报从“少量高门槛内容 + 强制商业解读”改为“证据合格内容按综合基础分分栏 + 只呈现原文事实”，并在每条资讯中明确展示可点击的原始来源和文章发布日期。

## 分栏与评分

简报继续使用选择器现有的综合基础分：

```text
0.45 × 重要性
+ 0.25 × 用户画像相关性
+ 0.20 × 商业机会
+ 0.10 × 证据质量
```

通过相关性、证据规则、去重和来源数量上限的常规条目不再以 6 分作为最低入选门槛。简报最多保留画像配置规定的条目数，并按现有最终排名排序：

- 综合基础分大于等于 6：今日必读
- 综合基础分小于 6：今日新闻

重大风险条目仍可绕过常规最低分，但只在上述两个栏目中出现一次，不再单设重复栏目。每条内容在事实快照中保存结构化综合基础分，渲染器不得从说明文字中反向解析分数。

## 每条资讯的内容

AI 二次处理只允许生成：

- `发生了什么`：用中文集中说明事件本身。
- `关键事实`：原文明示的企业、产品、市场、时间、技术、价格、渠道等信息，使用零到若干条短句；没有明确事实时返回空列表。

不再生成或展示三句摘要、对中国企业的意义、研发意义、机会信号、风险信号和建议动作。旧事实快照中的这些字段继续兼容读取，但新生成结果会清空它们，模板不再渲染它们。

## 来源与日期

每条资讯展示：

- 原始来源：优先使用发现查询识别出的发布者名称，其次使用直连来源名称，再次使用作者或域名；名称链接到解析后的原文 URL。
- 发布日期：将 `published_at` 统一转换为北京时间，格式为 `YYYY-MM-DD HH:mm（北京时间）`。
- 市场、分类和标签继续保留。

Markdown、HTML、飞书和微信所依赖的统一事实快照必须保持一致。

## 人工精选直连来源问题

最近一次运行中，直连来源在抓取阶段产出为零，主要原因是：

1. 网站返回 HTTP 拒绝或页面地址失效。
2. 多站共用的通用 HTML 选择器与实际页面结构不匹配。
3. 页面日期缺失、格式无法解析，或文章超出当前窗口。
4. 自适应回溯按所有来源总候选数触发，发现查询的高产出阻止了低产直连来源扩大窗口。

解决工作应作为独立的来源可靠性迭代：

1. 优先将有 RSS、Atom、JSON API 或 sitemap 的来源从 HTML 抓取切换到稳定入口。
2. 对保留的 HTML 来源逐站维护列表页、文章链接、标题、日期和正文规则，并增加离线页面夹具测试。
3. 将访问受限、付费墙或持续失效的来源标为“发现查询监测”或停用直连，不伪装成可抓取来源。
4. 将自适应回溯改为按来源或来源组判断，使精选来源可独立扩展至 72/168 小时。
5. 在运行报告中分别统计直连、发现查询和官方来源的抓取、相关、入选数量。

本次实现只修改简报分栏、事实型 enrichment、来源与发布日期展示；直连来源逐站修复另行实施和验收。

## 验收

- 6.0 分条目进入“今日必读”，5.99 分条目进入“今日新闻”。
- 低于 6 分但通过证据和相关性规则的条目可进入最多 20 条的候选集。
- 每条只出现“发生了什么”和非空的“关键事实”，不出现旧的分析型栏目或“三句摘要”。
- 原始来源显示为可点击名称，发布日期显示为北京时间。
- Markdown、HTML、飞书输出及端到端事实快照测试通过。
